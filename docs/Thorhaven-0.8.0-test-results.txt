Thorhaven 0.8 Preview — verification report
Date: 2026-10-03

389 automated checks passed:
- 102 existing Android integration checks against the final signed release.
- 43 previous 0.5 feature checks.
- 75 previous 0.6 feature checks.
- 75 previous RGB settings, animation, transport, backup, UI and service checks.
- 72 new RGB tools checks, including three real document-provider exchange checks.
- 12 real Android-consent, projection, PNG and silent-MP4 runtime checks against the final signed release.
- 10 self-tests from the native helper extracted from the final signed APK.

Environment: dedicated Android 15 / API 35 ARM64 emulator. Primary logical display 0: 1920x1080 at 240 dpi. Secondary public display 2: 1240x1080 at 240 dpi. Root Shizuku and a Linux uinput fixture support the existing controller and display integration tests. The debug-only document provider used by feature backup/export tests is excluded from the release APK.

The previous RGB suite validates the portable schema, all effects, preset/app limits, backups and the ordinary foreground-service lifecycle. The new RGB tools suite checks direct preset editing, shared-app routing, duplication, Unicode names, app search, transactional limits and concurrent preset/assignment updates. The styles-only bundle tests cover strict schema/field/type checks, UTF-8 byte bounds, unknown payload rejection, capacity, fresh IDs and deep-copy preservation.

Real ContentResolver exchange tests use the debug-only DocumentsProvider: the production activity-result handler exports exact Unicode styles-only bytes, an actual import confirmation Cancel leaves data unchanged, and Add merges fresh IDs against current settings while preserving a setting changed after the dialog opened. These are result-handler/provider integration tests, not an end-to-end file-picker selection test.

Independent-zone transport tests validate all four channel values before any commands, exact six fixed-node writes, stock-restoration scaling, no-create operations and partial write errors through a recording runner. Deterministic diagnostic tests cover all six modes, 8/24-second bounds, channel/zone order and modest intensity. Real Android service tests with recording backends exercise timeout, screen-off cancellation, no wake restart, queued-stop/dialog cancellation, in-flight stop, first-write error and stock recovery gating. Finishing the diagnostic's secondary-display activity restores before its normal deadline. A setup-failure cancellation-state bug and a window-detach cleanup bug found during independent review were fixed before final validation. No physical LED nodes are written by tests.

Real screen-capture regression tests use fresh Android sharing prompts, verify generated main-screen pixels and cropped PNG output, and produce a playable silent 1280x720 MP4 with a duration checked from its media metadata. Closing Screen Lab releases projection/reader/recorder/frame resources. No capture-consent bypass is used.

The released signed 0.7 APK and the final signed 0.8 APK both actually render the same seeded Unicode note and original guide. The forward update preserves the app UID, English language, app volume setting, exact original guide bytes and the saved RGB preset/app assignment. The signing certificate matches prior previews; Android version code is 8. Release build and release lint succeed. APK inspection confirms no Internet or microphone permission and no debug provider or instrumentation classes. RGB declares a local-purpose foreground service; it does not add screen/audio capture or new dependencies.

Limits: no physical AYN Thor was attached. Physical LED colors, both zones, direct-node permissions, PServer response and recovery behavior, stock/other lighting-controller conflicts and brightness compatibility remain experimental and require Thor testing. Firmware support cannot be inferred from recorded transport tests or a preview. Root/AYN lighting updates are limited to 2 per second; direct access can request 2, 5 or 10. Stock restoration recreates validated AYN colors/on-off/master brightness, not another application's animation. Process termination can delay restoration until the recovery action is used. Fan/CPU/thermal, injected-input acceptance and capture performance limitations remain. Daily backup scheduling is configuration/execution/retention-tested, not a multi-day soak.

Detailed results follow. Raw diagnostic values retain their original app/internal language.
