This is a milestone release candidate and a GitHub pre-release. It is not a claim of physical AYN Thor validation.

Environments: dedicated ARM64 Android 15 / API 35 and Android 11 / API 30 emulators. Both have primary logical display 0 at 1920x1080/240 dpi and secondary public display 2 at 1240x1080/240 dpi. Repeated new-feature and capture checks on the two SDKs are counted separately, not as distinct features. Legacy controller/display integration uses root Shizuku and a Linux uinput fixture on API 35.

The new candidate suite covers actual English/Dutch UI controls, independent per-game journals/checklists, strict bounded models, fresh-state mutations, editable normalized sketches, cancelled strokes, undo/redo, fixed PNG aspect, real document-result PNG bytes, export nonce ownership, and stale/cross-Activity results. Setup tests exercise live display assignment, bounded fifteen-second windows and real display removal with isolated test displays; temporary system permissions/display settings are restored. Shortcut payload/target checks do not request a real launcher pin. Storage tests use real persisted SAF permissions, a controlled test DocumentsProvider and production ContentResolver/result handlers for read/write revocation, grant overlap, unknown sizes, overflow, bounded/cancelled traversal, CSV escaping, disc ordering, M3U references and safe creation failures. Provider fixtures and instrumentation are absent from the release APK. File-picker selection itself is not automated.

Readiness checks reject duplicate keys, malformed JSON, invalid UTF-8, wrong numeric types, unknown fields, oversized settings, inconsistent ZIP central directories, truncated archives and corrupt CRCs before applying data. Real app-note editor replacement and Activity recreation preserve drafts. Failed launch checks leave global profile side effects unchanged, invalid pairs cannot partially launch, and delayed stale pair callbacks are cancelled.

Capture tests run against the signed release with real Android screen-sharing prompts. They exercise denied consent, late approval after emergency stop, fresh restart, obsolete queued starts, projection revocation and resource cleanup. They inspect generated pixels and a cropped PNG, and produce playable silent 1280x720 MP4s whose durations are checked using Android media metadata. No consent bypass or microphone permission is used.

The signed released 0.8 and signed final candidate both actually render the same seeded Unicode note and original guide. The forward update preserves the installed app UID, language, app volume, favorite, display roles, checklist, exact guide bytes, guide reading settings and original RGB preset/app assignment. Certificate continuity and Android version code 9 are verified. The release build succeeds; release lint reports 0 errors and 95 warnings (including existing synchronous SharedPreferences and platform API guidance). APK inspection confirms no Internet permission, microphone permission or test-only providers/classes.

Limits: no physical AYN Thor was attached. Physical RGB colors/zones, direct nodes, AYN bridge and firmware support, lighting-controller conflicts, stock recovery, vendor display/input behavior and capture performance still require Thor testing. RGB transport uses recording runners; existing controller tests use a Linux fixture. Launcher confirmation, Android's picker UI, actual emulator multi-disc switching and long-term battery/backup behavior need manual validation. Storage reports cover only the granted folder and are explicitly partial when bounded; provider calls already in progress may finish before cancellation. A failed M3U write can leave its newly created incomplete file, but never deliberately overwrites existing discs. Game cards launch an installed app; ROM choice stays with that app. Screen Lab captures Android's primary display, which may differ from the physical Top assignment.

Detailed results follow. Raw diagnostic text retains its original language.
