Thorhaven 0.6 Preview — verification report
Date: 2026-10-03

242 automated checks passed:
- 102 existing Android integration checks, rerun against the final signed release.
- 43 previous tool regression checks.
- 75 new tool, validation, backup, UI and cross-display checks.
- 12 real Android-consent, projection, PNG and silent-MP4 runtime checks against the final signed release.
- 10 native controller-helper self-tests.

Environment: dedicated Android 15 / API 35 ARM64 emulator. Main logical display 0: 1920x1080 at 240 dpi. Secondary public display 2: 1240x1080 at 240 dpi. Root Shizuku and a Linux uinput test fixture support the integration tests. A debug-only document provider is used for feature export/backup tests and is absent from the release APK.

New tool checks cover sequential macro validation and cancellation, finite turbo and runtime hold-capability probing, exact user macro names, typed key/pointer commands, actual top-screen pointer bounds from a lower context, separate display dimensions, cropped preview allocation, padded image buffers, original-document export, guide rename/reader/bookmark/marker backup, status privacy and sampled-session CSV exports.

Real capture checks use Android's actual screen-sharing prompts. A generated primary-screen color pattern is captured into a live frame and cropped PNG. Recording remains active until its lab is closed, produces a playable 1280x720 MP4 with a measured duration of approximately 3.7 seconds, has no audio track and releases projection/reader/recorder resources. A cross-display compatibility-bounds bug found during this test was fixed; the complete final suites were rerun. No capture-consent bypass is used.

A released signed 0.5 baseline and the final signed 0.6 APK both actually read and render the same Unicode note and original guide. The forward installation keeps the app UID, English language, app volume setting and exact original file bytes. The certificate matches all prior previews; Android version code is 6. Release build and release lint complete successfully. APK inspection confirms there is no Internet/microphone permission and no debug provider or instrumentation class.

Limits: no physical AYN Thor was attached. Actual Thor input acceptance, fan/CPU/RGB behavior, encoder availability and capture performance still need device testing. Hardware transitions and duration/pointer command execution use recording transports or hardware fixtures; these are not evidence of physical firmware support. The daily backup scheduler is tested for configuration/execution/retention, not a multi-day scheduling soak. Silent recording is limited to the main/default display, 3 minutes or 96 MB; its crop is not applied to MP4. Secure content may be black.

Detailed results follow. Diagnostic status values in raw test output preserve the app's internal wording.
