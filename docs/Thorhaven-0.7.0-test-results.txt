Thorhaven 0.7 Preview — verification report
Date: 2026-10-03

317 automated checks passed:
- 102 existing Android integration checks against the final signed release.
- 43 previous 0.5 feature checks.
- 75 previous 0.6 feature checks.
- 75 new RGB settings, animation, transport, backup, UI and service checks.
- 12 real Android-consent, projection, PNG and silent-MP4 runtime checks against the final signed release.
- 10 self-tests from the native helper extracted from the final signed APK.

Environment: dedicated Android 15 / API 35 ARM64 emulator. Primary logical display 0: 1920x1080 at 240 dpi. Secondary public display 2: 1240x1080 at 240 dpi. Root Shizuku and a Linux uinput fixture support the existing controller and display integration tests. The debug-only document provider used by feature backup/export tests is excluded from the release APK.

The RGB suite validates strict schemas and numeric/boolean types, independent colors/brightness/enable states, all seven effect calculations, specified battery/charging input arithmetic, unknown battery behavior, preset/app limits, exact user names, atomic invalid-import rejection and complete backup round trips. Fixed-node writer checks use a recording shell runner and cover both physical zones per stick, bounded channels, missing nodes, no-create writes, invalid payload rejection and partial error reporting. They do not write real LEDs.

The real foreground RGB service runs on Android with an injected recording backend. Tests verify background-thread work, assigned app selection, empty-foreground/global fallback, Stop-only intents, no queued frames after stopping, stopping during an in-flight write, restoration after a write error, and cancellation before service creation. Serialized session tests cover the recovery journal before the first write, screen-off black-frame deduplication, timer expiry, current stock settings taking precedence and retained recovery state after failed restoration. A rapid start/stop foreground-service timing bug and an empty-foreground fallback bug found during validation were corrected before the final RGB suite passed.

Real screen-capture regression tests use fresh Android sharing prompts, verify generated main-screen pixels and cropped PNG output, and produce a playable silent 1280x720 MP4 with a measured duration of 3667 ms. Closing Screen Lab releases projection/reader/recorder/frame resources. No capture-consent bypass is used.

The released signed 0.6 APK and the final signed 0.7 APK both actually render the same seeded Unicode note and original guide. The forward update preserves the app UID, English language, app volume setting and exact original guide bytes. The signing certificate matches prior previews; Android version code is 7. Release build and release lint succeed. APK inspection confirms no Internet or microphone permission and no debug provider or instrumentation classes. RGB declares a local-purpose foreground service; it does not add screen/audio capture or new dependencies.

Limits: no physical AYN Thor was attached. Physical LED colors, both zones, direct-node permissions, PServer response and recovery behavior, stock/other lighting-controller conflicts and brightness compatibility remain experimental and require Thor testing. Firmware support cannot be inferred from recorded transport tests or a preview. Root/AYN lighting updates are limited to 2 per second; direct access can request 2, 5 or 10. Stock restoration recreates validated AYN colors/on-off/master brightness, not another application's animation. Process termination can delay restoration until the recovery action is used. Fan/CPU/thermal, injected-input acceptance and capture performance limitations remain. Daily backup scheduling is configuration/execution/retention-tested, not a multi-day soak.

Detailed results follow. Raw diagnostic values retain their original app/internal language.
